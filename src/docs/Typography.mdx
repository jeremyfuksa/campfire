# Typography

Four families across two deployment contexts, with strict rules about where each family is allowed. Two grotesks (Hanken Grotesk + Work Sans) split the sans-serif workload by **role**, not by surface, so the same page can use both without context-switching feeling jarring.

## The role split

| Role | Family | Token | Mechanism |
| --- | --- | --- | --- |
| Body prose, ledes, captions, blockquote | **Hanken Grotesk** | `--font-body` | Applied to bare `<p>`, `<figcaption>`, `<blockquote>` in `globals.css` |
| Labels, buttons, navigation, software headings (h1–h6), eyebrows | **Work Sans** | `--font-sans` | Default on `<body>`; everything inherits it unless overridden |
| Editorial display (`editorial-h1`–`h3`, pullquote text, metric values) | **Fraunces** | `--font-heading-editorial` | Explicit `font-family: var(--font-heading-editorial)` on editorial elements only |
| Code, raw token values, `<kbd>`, tabular numerics | **Fira Code** | `--font-mono` | Applied to `<code>`, `<kbd>`, `<samp>`, `<pre>` |

## The body/UI test

When unsure which family an element gets:

> Is this text a paragraph of prose, **OR** a label / heading / affordance?

- Prose → **Hanken Grotesk** via `--font-body`.
- Label / heading / affordance → **Work Sans** via `--font-sans` (the inherited default, so no class needed).

There is no third category. If you find yourself reaching for one because it "feels right" without the test giving a clear answer, the design probably needs sharpening, not a font choice.

## Fraunces super wonk

Editorial Fraunces uses the variation `'opsz' 144, 'SOFT' 100, 'WONK' 1`:

- **`opsz` 144** — full display-grade optical sizing. Engages the most pronounced display features.
- **`SOFT` 100** — maximally soft, rounded terminals. Warms the letterforms.
- **`WONK` 1** — engages the WONK alternates: the curling `t`, the looping `g`, the playful `y`.

The full variation is exposed as `--editorial-font-variation`:

```css
font-family: var(--font-heading-editorial);
font-variation-settings: var(--editorial-font-variation);
```

## Don'ts

- Don't mix Hanken Grotesk and Work Sans by gut. The split is mechanical — prose vs. UI/label/heading/affordance.
- Don't use Hanken Grotesk for headings. Software h1–h6 are Work Sans; editorial h1–h3 / pullquote / metric are Fraunces.
- Don't use Fira Code on non-technical UI (CTAs, links, badges, navigation, eyebrows, dates, hero copy, body prose).
- Don't use Fraunces in software UI surfaces.

See `design.md` for the complete typography rules and rationale.
