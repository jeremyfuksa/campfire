# Layout

Campfire uses an 8px-derived rhythm expressed through a 4px base unit. The 4px quantum gives finer control for icon alignment and form-field interiors without losing predictable rhythm at component scale.

## Grid

12-column max-width container at **`80rem` (1280px)**. Gutters scale from `1rem` on mobile to `1.5rem` on desktop.

```tsx
<div className="max-w-[80rem] mx-auto px-4 md:px-6">
  <div className="grid grid-cols-12 gap-4 md:gap-6">
    {/* 12 column slots */}
  </div>
</div>
```

## Application chrome

Reserved dimension tokens for app shell:

| Slot           | Token                  | Value     |
| -------------- | ---------------------- | --------- |
| Header         | `--height-header`      | `5rem`    |
| Secondary nav  | `--height-secondary-nav` | `3.75rem` |
| Sidebar        | `--width-sidebar`      | `16rem`   |

## Spacing scale

Token-driven; maps 1:1 to Tailwind utility classes.

| Token | rem | px | Tailwind class |
| --- | --- | --- | --- |
| `--spacing-xxs`   | `0.25rem` | 4   | `p-1`, `gap-1`   |
| `--spacing-xs`    | `0.5rem`  | 8   | `p-2`, `gap-2`   |
| `--spacing-sm`    | `0.75rem` | 12  | `p-3`, `gap-3`   |
| `--spacing-md`    | `1rem`    | 16  | `p-4`, `gap-4`   |
| `--spacing-lg`    | `1.25rem` | 20  | `p-5`, `gap-5`   |
| `--spacing-xl`    | `1.5rem`  | 24  | `p-6`, `gap-6`   |
| `--spacing-xxl`   | `2rem`    | 32  | `p-8`, `gap-8`   |
| `--spacing-xxxl`  | `2.5rem`  | 40  | `p-10`, `gap-10` |
| `--spacing-huge`  | `3rem`    | 48  | `p-12`, `gap-12` |
| `--spacing-giant` | `4rem`    | 64  | `p-16`, `gap-16` |

## Named layout slots

Use these instead of raw spacing tokens for chrome-level layout decisions:

```css
var(--spacing-container-padding)  /* 1.5rem — outer container padding */
var(--spacing-card-gap)           /* 1rem — gap between cards in a grid */
var(--spacing-section-margin)     /* 4rem — vertical rhythm between sections */
```

## Density

Components default to a **comfortable** density. A future `compact` variant can be introduced by halving vertical padding tokens without retouching component code.

## Containment

Every page has at most one full-bleed surface. Cards, panels, and tables sit inside max-width containers so line lengths stay readable on ultra-wide displays.

## Responsive breakpoints

Tailwind defaults — no custom breakpoints. Most components are mobile-first; explicit breakpoint utilities (`md:`, `lg:`, `xl:`) handle desktop layouts.

```
sm   640px
md   768px
lg   1024px
xl   1280px  ← also the max-width container
2xl  1536px
```

## Layout primitives in the library

Use these instead of hand-rolling layout structures:

- **`<PageWithSidebar>`** — left sidebar + main content shell (used by app surfaces).
- **`<Card>` / `<CardHeader>` / `<CardContent>` / `<CardFooter>`** — Level 1/2 surfaces.
- **`<Sheet>` / `<Drawer>` / `<Dialog>`** — overlay primitives (Radix-backed; correct focus management).
- **`<ResizablePanelGroup>` / `<ResizablePanel>` / `<ResizableHandle>`** — split panes.
- **`<ScrollArea>`** — themed custom scrollbar.

See the **Components** section for stories demonstrating each.
